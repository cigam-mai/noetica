# Noetica — Stewardship and Canonical Integrity

**Version 1.0 — November 25, 2026**

## Purpose

Noetica welcomes exploration, criticism, research, and new ideas. Openness does not require surrendering the integrity of the founding record.

This policy distinguishes the canonical Noetica materials from commentary, proposals, adaptations, and community-created works.

## 1. Canonical works

The canonical record consists of the documents and reference materials identified as foundational in this repository, including:

- The README and project introduction
- The Founding Declaration
- The machine-readable Noetica Reference
- The project changelog and recorded founding history

The versions in the repository's default branch, together with their Git history and tagged releases, constitute the project's maintained canonical record.

No outside copy, fork, translation, adaptation, or commentary becomes canonical merely by using the Noetica name or vocabulary.

## 2. Stewardship and changes

Changes to canonical materials are made only by repository maintainers with authorized write access.

Proposed changes should be submitted for review rather than represented as official changes before acceptance. Accepted changes should:

- Have a clear explanation and attribution.
- Preserve the prior history through normal version control.
- Be recorded in the changelog when they materially affect the project.
- Identify substantive changes to definitions, principles, or founding history.

Foundational definitions and historical records should not be silently rewritten. Corrections should be transparent and traceable.

## 3. Community participation

Noetica welcomes:

- Discussion, criticism, and independent interpretation.
- Research and educational use.
- New concepts, proposals, tools, and independently authored works.
- Contributions submitted for consideration.

Community contributions remain distinct from canonical materials until reviewed and accepted by an authorized maintainer. A proposal, pull request, fork, or discussion is not itself an official amendment.

Contributors must have the rights needed to submit their work and must identify third-party material. Inclusion in the canonical repository requires agreement to the applicable licensing terms.

## 4. Copies, forks, and adaptations

The canonical content is governed by the project's Content License. Under the stated CC BY-ND 4.0 terms, unmodified licensed material may be redistributed with attribution, while adapted material may not be shared under that license.

Independent works may discuss or build upon Noetica's ideas, subject to applicable law. They should not be presented as official canonical documents or imply endorsement.

## 5. Repository security

The repository owner should limit write access to trusted maintainers and review access periodically. Where GitHub repository features and plan support permit, the owner should configure branch protection or repository rules for the default branch, including:

- Require changes to arrive through pull requests.
- Require at least one approval before merging.
- Require review of the latest changes before merge.
- Restrict direct pushes and force pushes.
- Prevent deletion of the default branch.

These are recommended GitHub settings; this document does not itself configure them. Repository permissions and platform controls must be checked in GitHub.

## 6. Historical integrity

The project history is part of the founding record. Material changes should be documented rather than concealed. Prior canonical versions should remain traceable through Git history and, where appropriate, version tags.

## 7. Scope and limitations

This policy describes project practice. It does not create legal ownership over ideas, guarantee trademark protection, or override the repository's actual access controls and applicable law.

The goal is straightforward:

**Noetica should remain open to new ideas, but its canonical history must remain authentic, attributable, and traceable.**
